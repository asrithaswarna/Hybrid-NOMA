# GNN-Based Dynamic User Pairing and Slot Assignment for Hybrid NOMA Networks

A Graph Neural Network (GNN) that learns to pair users and assign resource slots in a hybrid NOMA cell (PD-NOMA + SCMA + OMA fallback). The model is trained on synthetic wireless-channel data and benchmarked against OMA, random, near-far, greedy and exhaustive-search baselines.

## Project Overview

In Non-Orthogonal Multiple Access (NOMA), several users share the same time-frequency slot. Performance depends heavily on *which* users are paired and *which slot* they receive. Finding the best pairing by exhaustive search grows factorially with the number of users, which is too slow for real-time scheduling.

This project models the cell as a graph (users = nodes, user-to-user relations = edges) and trains an edge-conditioned GNN to predict pairing affinities and slot preferences. A deterministic post-processor then converts the predictions into a valid schedule (no duplicate users, slot capacity respected, odd user counts handled). The GNN is compared with classical baselines in terms of sum rate, fairness, outage and inference time.

## Features

- Synthetic wireless network simulator (path loss + Rayleigh fading), no external dataset needed
- Edge-conditioned GNN for user pairing and slot preference prediction
- Hybrid scheduler choosing between PD-NOMA (with imperfect SIC), SCMA (MPA detector) and OMA per allocation
- Benchmark against OMA, Random, Near-Far, Greedy and an exhaustive-search Optimization Oracle
- Classical ML comparison (Linear, Ridge, Lasso, Decision Tree, Random Forest) for per-user rate prediction
- K-means, DBSCAN and PCA clustering of user channel features
- Optional FastAPI service for the Random Forest rate model
- Automated tests (32 tests, pytest) and auto-generated figures/metrics

## Technologies Used

Python 3.9+, PyTorch, NumPy, SciPy, scikit-learn, pandas, NetworkX, Matplotlib, PyYAML, FastAPI/Uvicorn, pytest

## Dataset Details

The project uses a **synthetic dataset that is generated inside the code** every time it runs. There is nothing to download.

- Generated by `DatasetGenerator.generate_split()` in `src/training.py` (called from `main.py`).
- Each sample is one random cell: base station at (0, 0); users placed uniformly by area in an annulus of 20 m to 500 m.
- Channel: log-distance path loss (exponent 3.5, 2.4 GHz) with i.i.d. complex Rayleigh fading.
- System: 10 MHz bandwidth split into 5 slots, 1 W BS power, -174 dBm/Hz noise density, 5 dB noise figure.
- Graph: one node per user (6 features), fully connected user-to-user edges (4 features).
- Labels (pairing and slot targets): produced by the exhaustive-search oracle (`src/optimization.py`).
- Default split: 200 train / 40 validation / 50 test networks, fixed by `--seed` (default 42) for reproducibility.
- Optional: `--data-source csv --dataset data/example_users.csv` runs the classical/clustering workflows on a per-user CSV.

Limitation: results reflect the configured simulation model and are not measurements from real hardware.

## How to Run

```bash
# 1. Install dependencies (Python 3.9+)
pip install -r requirements.txt

# 2. Full run used for the reported results (10 users, 5 slots, 25 epochs)
python main.py --users 10 --epochs 25 --slots 5 --seed 42 --output results

# 3. Quick check (about a minute)
python main.py --users 6 --epochs 2 --slots 3 --output results_quick

# 4. Other modes
python main.py --mode compare    --users 6 --output results_compare    # Linear/Ridge/Lasso/Tree/Forest
python main.py --mode clustering --users 6 --output results_clusters   # K-means, DBSCAN, PCA
python main.py --mode evaluate   --model-path results/best_gnn_model.pt --users 10 --slots 5 --output results

# 5. Run the tests
python -m pytest tests -v

# 6. Optional API (needs results/classical_models/random_forest.joblib from step 2)
uvicorn api.main:app --reload
```

All settings can be changed in `config.yaml`. The notebook `notebooks/hybrid_noma_experiment.ipynb` can be used to run the experiment in Jupyter/Colab.

## Results

Reference run: 10 users, 5 slots, 25 epochs, seed 42, 50 test networks (`results/metrics/benchmark_results.csv`).

| Method | Sum Rate (Mbps) | Jain's Fairness | Outage | Inference (ms) |
|---|---|---|---|---|
| OMA | 19.49 ± 8.28 | 0.335 | 50.4% | 0.13 |
| Random Pairing PD-NOMA | 16.15 ± 6.70 | 0.530 | 3.0% | 0.72 |
| Near-Far NOMA | 16.29 ± 6.94 | 0.508 | 2.2% | 0.43 |
| Greedy Sum-Rate NOMA | 16.75 ± 5.62 | 0.505 | 11.0% | 0.84 |
| Optimization Oracle (exhaustive) | 17.59 ± 7.02 | 0.523 | 6.4% | 343.35 |
| **Proposed GNN NOMA** | **17.64 ± 6.87** | 0.523 | 10.2% | 13.29 |

Key observations:
- The GNN reaches the sum rate of the exhaustive oracle (17.64 vs 17.59 Mbps) while being about 26x faster (13.3 ms vs 343 ms).
- OMA shows a high sum rate only because it serves one user per slot; about half of the users are in outage and fairness is lowest (0.335).
- The GNN's outage (10.2%) is higher than Random and Near-Far pairing (2-3%), a trade-off for its higher sum rate.
- Classical rate regression (test split): Linear/Ridge/Lasso R² ≈ 0.876; Decision Tree R² ≈ 0.999; Random Forest R² ≈ 0.9999 (`results/classical_models/classical_model_comparison.csv`).
- SCMA detector BER falls from about 0.43 at -5 dB to about 0.003 at 20 dB (`results/figures/scma_ber_curve.png`).

Figures are in `results/figures/`: `network_topology.png`, `training_loss_curves.png`, `sum_rate_benchmark.png`, `scma_ber_curve.png`.
